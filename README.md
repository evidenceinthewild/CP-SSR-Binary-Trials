# CP-SSR-Binary-Trials

Reproducibility code for the manuscript:

> **Final Critical-Count Calibration in Single-Arm Binary
> Promising-Zone Designs**

Repository: <https://anonymous.4open.science/r/CP-SSR-Binary-Trials-8DB8/>

This repository contains simulation helpers, exact-enumeration operating
characteristic (OC) calculations, and the Quarto source for the manuscript
and all of its tables and figures.

Individual files can be browsed and downloaded from the link above. The
anonymous proxy must be refreshed from the current repository revision before
each blinded submission.

## Summary of the paper

Promising-zone sample size re-estimation is often paired with a one-sided
one-proportion score z-test in single-arm binary trials. Exact enumeration
shows that the final z-test already has 5.80% Type I error at the planned
fixed sample size in the representative oncology design, before any interim
look or adaptation. Under the primary interim-estimated-effect convention,
the adaptive CP-z design ranges from 5.55% to 5.69%.

Comparisons against fixed-N references show that adaptation can either
increase or decrease the attained Type I error. Within frozen CP and
predictive-probability adaptation mappings, final-rule contrasts are larger
than the CP-versus-PP mapping contrast in the base design. Exact-binomial
finals and an inverse-normal combination test using exact stagewise p-values
control Type I error conservatively; a mid-p combination variant can exceed
the nominal level. Across five design configurations, the sign of the
score-z test's attained level relative to alpha changes, so every complete
design requires design-specific exact evaluation. The critical-count bias
itself does not change sign: the score-z count is never larger than the
exact-binomial count in any configuration examined.

The algorithms in this repository are research implementations for the
manuscript. They should not be treated as documentation of any production
software implementation.

```
    ├── analysis.R              # exact-enumeration engine and simulators
    ├── params.R                # design parameters shared by both documents
    ├── interim_timing_sensitivity.R # exact one-look timing sensitivity
    ├── two_look_sensitivity.R # exact pathwise two-look CP sensitivity
    ├── standard_practice_sensitivity.R # practice-oriented sensitivities
    ├── independent_validation.R # standalone base-R validation
    ├── revision_analyses.R     # principal revision-analysis driver
    ├── regression_checks.R     # focused statistical regression checks
    └── make_anon.R             # derives the anonymous manuscript source
```

`R/analysis.R` is self-contained and can be sourced from R for ad-hoc
exploration without rendering either document. `R/params.R` is sourced after
it and fixes the design constants, so the manuscript and the supplement
cannot drift apart.

While the article is under anonymous review, the tracked copy of
`CP_PromisingZone_SSR_TypeIError.qmd` carries the anonymised manuscript
source, generated by `R/make_anon.R`. That script substitutes two things:
the author line and the paragraph naming this repository, which becomes an
anonymous proxy link. Both are restored after acceptance; nothing else
about the file changes.

**Build order.** The manuscript writes `_supplement_data.rds`, which the
supplement reads, so render the manuscript first:

```bash
quarto render CP_PromisingZone_SSR_TypeIError.qmd --to pdf
quarto render Supplementary_Material.qmd          --to pdf
```

Rendering the supplement without that file gives an explicit error rather
than a silent mismatch.

## How to render the manuscript

From the repository root:

```bash
quarto render CP_PromisingZone_SSR_TypeIError.qmd --to pdf
quarto render CP_PromisingZone_SSR_TypeIError.qmd --to html
quarto render Supplementary_Material.qmd          --to pdf
Rscript --vanilla -e 'for (p in c("tidyverse","gt","scales","patchwork","glue","latex2exp")) library(p, character.only = TRUE); capture.output(sessionInfo(), file = "session-info.txt")'
```

Render the manuscript before the supplement: the manuscript writes the
`_supplement_data.rds` handoff file that the supplement reads.

The first render performs the full exact-enumeration sweep over the
parameter grid and may take several minutes on a laptop. Subsequent
renders reuse cached chunks unless the chunk code, `R/analysis.R`,
`R/params.R`, `R/interim_timing_sensitivity.R`,
`R/standard_practice_sensitivity.R`, or `R/two_look_sensitivity.R` changes;
all five are part of knitr's cache key.
For a release build, add `--cache-refresh` to force full recomputation.

Run the focused regression checks before rendering:

```bash
Rscript --vanilla R/regression_checks.R
Rscript --vanilla R/interim_timing_sensitivity.R
Rscript --vanilla R/two_look_sensitivity.R
Rscript --vanilla R/standard_practice_sensitivity.R
Rscript --vanilla R/independent_validation.R
```

The standard-practice script evaluates a coherent continuity-corrected score
design, a finer posterior-threshold grid, historical-benchmark drift, and
post-adaptation estimation. When run directly it also performs a seeded Monte
Carlo cross-check against the primary exact operating characteristics.
The two-look script uses exact pathwise recursion for two prespecified CP
schedules. The independent-validation script uses only base R, sources no
manuscript code or parameter file, and reproduces six selected published
operating characteristics from a separate implementation.

## How to use the analysis code on its own

```r
source("R/analysis.R")

# Exact Type I error of a CP promising-zone SSR design with a z-test final.
# cp_oc_exact() enumerates the joint (x_int, x_rem) binomial distribution
# and returns operating characteristics deterministically (no Monte Carlo).
res <- cp_oc_exact(
  p_true   = 0.20,             # evaluate under the null (p_true = p0)
  cp_lower = 0.30,
  cp_upper = 0.80,
  cp_futility = 0.10,
  n_init   = 30L, n_int = 20L, n_max = 60L,
  p0 = 0.20, p1 = 0.40,
  alpha    = 0.05,
  cp_mode  = "estimated"       # see note below
)
res$power   # under p_true = p0 this is the Type I error
```

**Note on `cp_mode`.** The paper's primary analysis projects conditional
power under the *interim-estimated* response rate, following Mehta and
Pocock (2011), which is `cp_mode = "estimated"`. For backward
compatibility the argument still defaults to `"design"` (projection under
the design alternative `p1`), which the paper reports only as a
sensitivity analysis. Pass `cp_mode` explicitly to be sure which
convention you are using; the two give materially different operating
characteristics.

`bayes_oc_exact()` returns the same shape for the Bayesian PP design.
`cp_oc_post_final()` covers the symmetric variant (CP-driven SSR with a
Bayesian posterior final analysis) and returns the same quantities without
the sample-size percentiles. The Monte
Carlo simulators (`run_cp_scenario`, `run_bayes_scenario`) are useful
as a starting point for extensions where exact enumeration is awkward;
they take an explicit `n_sim` argument. Both implement a single interim
look, so supporting multiple looks would require extending them.
